Purpose and scope

Codemoji is a local Windows companion for expressive input in the Codex desktop app. Its optional Discord bot is intended to collect custom emoji, stickers and GIF references deliberately posted by an approved account in explicitly selected channels of an approved collection server. It is not intended to monitor direct messages, other servers or general conversations.

What the bot will receive and retain

Discord delivers message events and permitted history through its official bot API. Those events can include surrounding text and other metadata. The collector must validate server, channel and author scope before expression processing; raw message payloads and surrounding conversation text must not be retained or logged.

The intended collection records include:

  • Server, channel, source-message and expression identifiers needed for collection membership, updates and duplicate prevention.
  • Emoji or sticker names, animation or format information, and relevant media or provider-page references.
  • Source-reference membership used to reconcile edits, removals and duplicates. The initial bot collection does not infer favorites or usage counts from posts.

The saved Discord picker is separate from the manual-import Vault. Loading saved records reads the encrypted last-known collection locally. Loading media is a separate, explicit action that requests supported images or GIFs from narrowly restricted Discord CDN routes without the bot token. Previews and downloaded originals remain in bounded application memory until discarded. Provider webpages are not automatically resolved or downloaded; unsupported or expired references remain unavailable. Collection access does not grant rights to reproduce or redistribute someone else's content.

Storage and credentials

The bot credential is stored outside the project source in a device-local file encrypted with Windows DPAPI for the current Windows user. It is not included in project synchronization or public website files. Access is restricted to that user and Windows SYSTEM. This protects the file at rest, not against malicious software already running as the same user.

The staged collection store uses device-local Windows DPAPI encryption for the current Windows user, with scope-bound encryption, restricted filesystem access and encrypted atomic replacement files. It is outside synchronized project files. No plaintext collection checkpoint or raw-message log is written. The existing manual-import Codemoji Vault is unencrypted and separate; bot-derived records are not silently copied into it. Encrypted collection records from the completed test are retained until explicitly cleared.

Selecting a loaded item creates a temporary plaintext file so Codex can access it as an unsent draft attachment. These files are stored in a dedicated device-local staging directory with filesystem access restricted to the Windows user and SYSTEM, outside project synchronization and the manual Vault. They are not encrypted while staged. Cleanup on a later attachment operation removes recognized staging files older than 24 hours; files can remain longer if the application is not used again. Cleanup is not secure erasure, and does not remove operating-system recovery copies, backups or copies created by Codex.

Encryption at rest does not protect against malicious software running as the same Windows user, memory inspection, operating-system paging or crash capture. Scope and credential encryption are device-local; copying the encrypted files to another computer is not a supported synchronization method.

Third parties and sharing

Posts in a private Discord server are stored and processed by Discord under its Privacy Policy. Private server membership does not make those posts local-only.

No Codemoji-operated cloud collection service, advertising or analytics is configured. No cross-device transfer of bot-collected data is active. Explicit media loading contacts Discord's CDN; opening the picker alone does not fetch media or start collection.

Codemoji issues a paste request only, never an automatic send command. Codex may upload an attachment before the operator sends the message. Clipboard restoration is best-effort and cannot guarantee support for every private clipboard format. Service processing is governed by the selected service's settings and policies.

Retention, correction and deletion

Accepted expression references are retained in the selected personal collection until removed by source reconciliation or an explicit local clear. There is no automatic age-based expiration of the committed collection. Editing an accepted post replaces its expression membership. Deleting the final accepted post referencing an expression removes that expression from the collection when the deletion is processed; another accepted post can keep the same expression present. Independently imported manual Vault items are not affected.

While stopped or disconnected, saved state is last-known, not a live mirror. The completed pilot accepted only new posts from the approved author after its start boundary; it did not enumerate existing history or import older posts through edits. That mode may fetch the complete snapshot of a newly accepted post to process its expressions or edits. Retained records from an earlier run must not be silently erased to start a new-only pilot.

A separate catch-up mode is staged but is not authorized for the first pilot. That mode rescans approved history and rechecks missing known posts before making entries available. Access errors, timeouts and rate limits are not treated as deletions. Its initial history bound is 1,000 total scanned posts per startup, not 1,000 expressions. The separate encrypted store is capped at 1,000 retained expression-bearing source posts, 5,000 references and a 4 MiB checkpoint, across sessions; these are prototype safety bounds, not a manual-Vault limit. Incomplete or oversized scans fail closed instead of silently truncating. Unexpected disconnection makes the collection unavailable rather than automatically resuming.

The existing Clear collection operation removes dedicated encrypted collection records and recognized interrupted-save remnants; it does not remove the credential, configuration, independent manual Vault, original Discord posts, staged attachment files or copies created by Codex. Staged files follow the separate cleanup rule above. Clear requires confirmation, is not secure erasure, and does not erase operating-system recovery copies or external backups. Multiple-file clearing can partially complete if an I/O failure occurs. This revision does not enable live collection, synchronization or public media sharing.

At storage-session startup, recognized temporary saves are removed only after all candidates pass name, size, access and same-scope encryption checks under exclusive locks. They are never promoted into the committed collection. Damaged, foreign or unknown remnants block normal startup for review; confirmed clearing can remove recognized damaged remnants. Unknown names are not automatically deleted.

Stop disconnects this controller's collection session without deleting records. Clear removes local collection data without revoking the token or deleting source posts. Token reset or bot removal is performed separately through Discord. The staged panel does not start collection automatically when opened or at Windows sign-in.
